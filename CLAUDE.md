## Сообщения коммитов — вся экосистема мессенджера

Правила обязательны для Messenger (messenger-backend), Aura, Aurify, AuraSDK (aura-sdk), Plumbus, их SDK, плагинов, исполнителей, инфраструктурных и вспомогательных репозиториев, включая aura-binaries, aura-bug-report и aurify-plugin-sdk. Они действуют и в самостоятельных клонах, и во всех сабмодулях любой глубины, когда мы создаём в них коммиты. Расположение каталога и наличие собственного выпуска не меняют формат. Уже существующую историю и сообщения чужих коммитов не переписывать. На посторонние проекты эти правила не распространяются.

**Форма заголовка:** `тип(область): что изменилось для пользователя`. Область необязательна. Описание по-русски, одной строкой, без точки в конце. В теле — почему так и что было до этого.

| Тип | Когда | Влияние на версию при автоматическом расчёте |
|-----|-------|--------|
| `feat` | Новая возможность для пользователя или потребителя API/SDK: экран, режим, язык интерфейса, ручка API | минор |
| `fix` | Исправление сломанного поведения; дописанные переводы существующего языка | патч |
| `perf` | Стало быстрее или легче при прежнем поведении | патч |
| `тип!` или `BREAKING CHANGE:` в теле | Несовместимый формат или API, удалённая ручка, сброс настроек | при версии 0.x — минор, иначе мажор |
| `refactor`, `test`, `chore`, `ci`, `build`, `docs`, `style` | Технические изменения без новых возможностей и исправлений пользовательского поведения | не двигает |

Тип выбирается по результату для пользователя или потребителя библиотеки, а не по расширению файла. Смешанные изменения лучше разделить; если это невозможно, выбирается старший тип по влиянию на версию. Обновление ссылки на сабмодуль оценивается по изменениям, которые оно приносит: новая возможность — `feat`, исправление — `fix`, только техническое обновление — `chore` или `build`.

Без ID задач, ссылок на трекеры, названий проектов-доноров и строки `Co-Authored-By`. Коммитить только по просьбе пользователя и только свои изменения.

Формат обязателен даже там, где ещё нет автоматического расчёта версии. Наличие этого правила не означает, что скрипт выпуска существует в каждом репозитории. Для конкретного выпуска использовать его собственные манифесты и процедуру; не переносить требования к `package.json` на Rust, C++ или .NET. Номер сборки не заменяет версию продукта. Не переписывать историю ради изменения типов старых коммитов.
